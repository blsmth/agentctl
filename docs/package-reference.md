# Internal package reference

Per-package detail for `internal/`. CLAUDE.md carries a one-line map; this is the full text. For the source layout see [architecture.md](architecture.md).

- **tmux/** — All tmux interactions (sessions, windows, panes, keybindings, `display-popup`/`display-menu`). The per-window chrome bar (a two-row Bubble Tea pane docked at the bottom of each window) is gated by global config `chrome_bar` (default off, `chromegate.go`): off, the native tmux status line shows a plain window list; on, the status line is off and every window gets a bar. `LaunchChromeBar` reads the switch on each call (with it off it only records `main_pane`), and `agentctl apply-config` switches existing windows both ways. Session name is `tmux.SessionName` (`agentctl-<dir>`).
- **windowstate/** — Authoritative per-window hook state at `.agentctl/windows/<windowID>.json`. Written by hooks, read by the monitor.
- **winname/** — Computes the window name (glyph + instance) from windowstate and renames the tmux window inside the writer's transaction (`winname.Update`/`Transact`, `SyncName`).
- **state/** — The `state.json` snapshot the monitor writes each tick (agentctl readers build their view from `fleet.LoadAgents` and use a fresh snapshot only as optional token enrichment; also the one-release restore fallback), plus `AgentState`, the restore builders, and the snapshot types.
- **agent/** — Agent discovery from `~/.claude/agents/*.md` and project-local `.claude/agents/` (local shadows global); `Extends` composes agents.
- **sessions/** — Parses Claude Code's JSONL logs in every account's `projects/` dir (`~/.claude/projects/` by default) for summaries, metrics, and session metadata sidecars. Also owns session cost: `CostOfSummary` prices per request through `tokens.Lookup` (unknown model = unknown cost, never a Sonnet default) and `ClassifyBilling` assigns `metered`/`sub`/`free`; surfaced by `agentctl cost`. Pricing lives only in `internal/tokens`.
- **claudehome/** — Resolves Claude Code config dirs (`CLAUDE_CONFIG_DIR`), one per configured account: `Dir`, `All`, `Current`, and `Resolve` (flag > agent > `account_rules` on the repo root > dispatching window > `default_account`). Every transcript/settings path that used to hardcode `~/.claude` goes through it; shared content (agents, `settings.json`, …) still lives in `HomeDir()` and is symlinked into each account. agentctl never touches credentials (grep-tested). See [docs/configuration.md](docs/configuration.md#accounts-multiple-claude-logins).
- **config/** — Layered settings: project-local `.agentctl/config.json` over global `~/.config/agentctl/config.json`, reloaded every monitor tick. See [docs/configuration.md](docs/configuration.md); `internal/config` structs are the source of truth.
- **dispatch/**, **improve/** — `dispatch.RunComplete` (hook-spawned completion), plus dispatch/worktree orchestration; `improve.Run` starts a manual self-improvement session (never auto-triggered): `agentctl improve [<agent>] [--fleet] [--session] [--since] [--theme] [--template] [--model] [--backend] [--account] [--dry-run]` builds an evidence pack (`improve.Evidence`: closedlog outcome, audit denials/failures, cost, PR verdicts and session-audit findings through nil-able seams) into the prompt; the window opens unfocused unless started from the popup or hub (`LaunchSession`), records `spawned_by`, shows in the hub, and sweep closes it once idle; `cost --by agent` reports its spend as `improve:<agent>`.
- **harness/** — The agent program in a window: Claude Code (default) or pi. `Harness` owns everything program-specific: the launch command (fresh, restore, fork) and its env (`CLAUDE_CODE_*` lives in the Claude harness), `PrepareWorkspace` (Claude settings files through the launcher's writer; pi's embedded bridge extension `pi/agentctl-pi.ts`), hook payload decode to the canonical (Claude-shaped) payload plus output encoding (`EncodeDecision`), transcript location/parsing and pane classification. Callers check `Caps` (`NativeMessaging`, `Accounts`, `Backends`, `BlockedSignal`, ...) rather than names and degrade. Backends on pi: `dispatch.PrepareBackendFor` resolves and preflights them, and pi's `PrepareWorkspace` turns the `harness.Backend` into `AGENTCTL_PI_PROVIDER`, which the bridge registers (`Caps.RegistersBackends`). Selection: `dispatch --harness` > `agents.<name>.harness` (global-only) > frontmatter `harness:` > `claude`; recorded in windowstate/`restore.json` (empty = claude) and `AGENTCTL_HARNESS`. Every launch path (`dispatch.Launch`, `dispatch.Restore`, `improve.LaunchSession`, `cmd.LaunchWithResume`) goes through it; the Claude golden tests (`testdata/golden`, via `internal/tmux/launchtest`) pin its command lines and env. See [docs/configuration.md](docs/configuration.md#harnesses-claude-code-and-pi).
- **transcript/** — Leaf package normalizing non-Claude transcript records (pi session files) into Claude Code's JSONL shape; `logstream`, `sessions` and the HUD apply it per line, so tokens, cost and summaries work on any harness.
- **hooks/** — Claude Code hook handlers (`hooks.Dispatch`): write windowstate, fire notifications, validate Bash, derive done state. Harnesses other than Claude call them with `--harness <name>` (`hooks.SetHarness`): stdin decodes through `harness.DecodeHook` and decisions go out through `emitDecision`; the state logic is shared.
- **tui/** — Bubble Tea models: the fsnotify-fed chrome bar, menus, wizards, and full-screen browsers; the hub's `/` type-to-search filter (`fleet_search.go`).
- **render/** — Leaf package of presentation helpers shared by the chrome bar and the statusline so both render the same numbers.
- **statusline/** — Handles `agentctl statusline`, the command Claude Code pushes its JSON payload to (fast path before Kong). Renders `rich`, `complementary`, `full`, `mobile` (two phone-width lines: model/ctx/session length, 5h/7d/cost/account; `mobile_render.go`), or `minimal` per `statusline_format` and records pushed rate-limit and context data. Git branch is read from `.git/HEAD` with no subprocess; only the dirty count shells out, under a 150ms timeout. While `agentctl serve` has a live phone terminal or an open window detail screen on the window (marker in `<stateDir>/phone-viewed/`, `internal/phoneview`) and no laptop client views it, it renders `statusline_mobile_format` (default `mobile`); `tmux list-clients` runs only when a marker exists. Right-alignment (`statusline_align`) pads with U+2800 because Claude Code strips leading whitespace; see `padRune` and `rightAlignReserve` in `statusline.go`.
- **llm/** — Single-turn `llm.Completer` keyed on `llm.provider` (`ollama`, `claude`; empty = disabled). The Ollama client always sends `think:false`, sets `num_ctx`, and errors rather than return a blank or truncated completion. Consumers: the work journal, and `NousClient` (OpenAI-compatible chat completions on a `nous` backend, content only, never reasoning) for short titles; every failure is non-fatal. `NousClient` implements the optional `llm.UsageReporter` (usage from the response) and appends every call, failed ones too, to the `internal/llmusage` ledger (`<stateDir>/llm-usage/usage-<YYYY-MM>.ndjson`, attributed by `llmusage.WithMeta` in the context, priced at write time, `cost_usd` null when unknown, pruned at 90 days by housekeeping); `agentctl cost` reports it in its own Background LLM calls section, never in session totals.
- **shorttitle/** — 2-5 word row titles (`fleet.RecapLine.Title`, served as `title`), config `titles` (global-only). Generated by the async `hook-title` on Stop/UserPromptSubmit/SessionStart from the task or ticket (a bare window's first prompt, stored as windowstate `first_prompt`); the reply is `<kind> | <title>` (closed kind set, stored as `short_title.kind`, not drawn itself; review-pr windows are always `review`). A sub-agent window (`spawned_by` and `spawned_by_session` both set) gets its parent's row title as a prompt hint (`Input.ParentTitle`, not in `Hash`; `titleInput`/`parentTitle` in `internal/hooks/title.go`, same-runtime-dir lookup only, so `BackfillTitles` gets it too) so its title names its own piece, not the orchestrator's, and a role label from `shorttitle.Role(mode, kind)` (`review`/`research`/`fix`/`docs`/`tests`/`build`; `fleet.Row.ShortRole`, served as `role`), shown before the title on hub child rows and as the pill on the phone, never on bare/cron rows; stored in windowstate `short_title`, so readers never touch the network. At most two titles per window: the first, then one refinement at the first Stop from that response, after which `short_title.final` freezes it (no time-based or away_summary retitle; `/clear` resets it, resume/compact do not). Failures keep the title unfrozen under a retry backoff, a machine-wide hourly cap (`titles.hourly_cap`, default 120, `<stateDir>/titles/budget.json`; resume/compact SessionStart requests cannot take the last 30 slots, so a restore burst never starves new sessions), and an in-transaction claim so a double-registered hook sends one request. Windows no hook reaches (idle since before titles) are backfilled by `reconcile --housekeeping` (`hooks.BackfillTitles`, wired in `internal/cmd/reconcile.go`): live windows of this session only, at most 3 per 5-minute run, leaving 40 of the hourly cap to the hooks (30 for new sessions plus 10), final once the window has finished a turn. Untitled rows show the recap's first sentence, cut at a word boundary (`fleet.TruncateWords`, `truncateWords` on the phone). A human can rename a row from the hub (`R`, the row menu, or double-click its title; `internal/tui/fleet_rename.go`): `shorttitle.SetManual` writes `short_title` with `manual` (and `final`) through `windowstate.UpdateIn` in the row's own runtime dir (never creates a record). Manual titles are never replaced: `shorttitle.Due`/`Apply`, `hook-title`, `BackfillTitles` and the `/clear` reset all skip them, and fleet shows them whatever the recap source (`Row.ShortManual`). An empty save clears `short_title` so automatic titles resume. Each request is ledgered with feature `titles`, the window and its project. When `hook-title` runs it also refreshes the machine-wide price cache if it is over 24h old (`pricecache.RefreshIfStale`, once a day machine-wide, silent). No spawns; never uses the `claude` CLI. See [docs/configuration.md](docs/configuration.md#titles).
- **closedlog/** — Machine-wide NDJSON ledger of closed agent windows (`<stateDir>/closed/closed-<YYYY-MM>.ndjson`): `reconcile.Finish` appends one line per tracked window (shell/unidentifiable skipped, non-fatal, one `O_APPEND` write), with `reason` `cascade` for `close_children` kills (windowstate `closed_by`, set by the cascade before the kill) and `improve` for `agentctl improve` windows (windowstate Mode `improve`). `Load(since)` is newest first, deduped by `Key`, corrupt lines skipped; `Cache` re-reads on file change; housekeeping prunes at 90 days. Read by `agentctl status list --closed` and the hub's `C` Closed section, whose Enter resumes through the hidden `agentctl hub-resume` (`cmd.launchResume`, the `LaunchWithResume` path). Session teardown never reaches it.
- **pricecache/**, **llmusage/** — `pricecache` writes/fetches/refreshes the machine-wide Nous catalog copy under `<stateDir>/pricing` (`Refresh`, once-a-day `RefreshIfStale`); `llmusage` is the NDJSON ledger of agentctl's own LLM calls (`Append`, `Load`, `Prune`, `Cost`). Both resolve state paths lazily and are covered by `testenv` TestMains.
- **verdicts/** — Machine-wide NDJSON ledger of PR review verdicts (`<stateDir>/verdicts/verdicts-<YYYY-MM>.ndjson`, pruned at 90 days by housekeeping). The PostToolUse hook (`hooks.recordVerdict`, only for the `SendMessage` tool, one substring check first) appends a line when the body matches `REVIEW PR #N — VERDICT: MERGE|MERGE-WITH-FOLLOWUPS|BLOCKED|NEEDS-BRENDAN`; the author comes first from the reviewer's own windowstate `review` (`windowstate.ReviewTarget`: PR, head branch, repo, author window/agent/session/runtime dir, recorded by `dispatch --review-pr`), else the live window in the runtime dir whose windowstate records that PR (`pr_number`/`log_pr`), never a `gh` call, so unresolved authors are left empty. `ByAuthor` counts one verdict per (PR, reviewer session), the latest. Only a message that starts with the verdict line counts (a relayed quote does not); `Rounds: N` is parsed. The author is the window whose dispatch completion recorded the PR, else one whose transcript linked it (never a `review-pr` window; ties by lowest window ID). Read by `agentctl audit verdicts [--since 30d] [--json]` (a sibling of `audit log` and `audit report`; BLOCKED rate per author agent). `sessionaudit` ignores `tool_approved` records when merging and labels `denied_by: timeout` as an unanswered popup. Approval popups also write audit events: a timeout is `tool_denied` with `denied_by: "timeout"` (older records say `rule`), an approval is `tool_approved` with `source` `laptop|phone` and `duration_ms`.
- **claude/** — Persistent `claude` CLI subprocess client (NDJSON over stdio), retained as a non-default `llm` provider selectable only with `llm.provider: "claude"`. Kept deliberately as the basis for any future Go agent integration.
- **worktree/** — Git worktree create/remove/list/prune for isolated dispatch, under `<repo>/.worktrees/<slug>/`.
- **cleanup/** — Classifies worktrees (`empty`, `landed`, dirty, unpushed, …) so `agentctl cleanup` and SessionEnd reclaim only what is safe.
- **fleet/** — Cross-session aggregation behind `agentctl hub` and `agentctl status`, including pane classification (`ClassifyPane`).
- **mailbox/** — Per-window store for agentctl-originated notices (done/blocked backstop), delivered by the UserPromptSubmit/PostToolUse hooks. Agent-to-agent messaging is Claude Code's native `SendMessage`/`ListAgents`, not this package.
- **metrics/**, **metricsserve/**, **metricsproc/** — Prometheus registry, collectors and remote write; `metrics/events` is the hook-written transition log; `metricsserve` is `agentctl metrics serve`; `metricsproc` is its pidfile/lock/start plumbing. See [docs/monitor-architecture.md](docs/monitor-architecture.md#metrics-without-the-monitor).
- **notify/** — Desktop notifications from `notify_cmd` (`alerter` on macOS, `notify-send` on Linux).
- **serve/** — `agentctl serve`, the per-machine HTTPS server for the mobile web app: local CA + leaf certs, an optional Let's Encrypt wildcard for `serve.public_hostname` routed by exact SNI (`publiccert.go`, certmagic in `acme.go`), CIDR filter, device-cookie auth, CSRF, pairing over a 0600 control socket. Routes register through `Router` (`Public`/`Device`/`Write`); see [docs/design/mobile-web-app.md](docs/design/mobile-web-app.md). Start/stop live in the leaf `internal/servectl` (`serve start|stop|toggle`, prefix+`W`, the hub's `📱` indicator and `S` key) and switch phone access, not the process: stop writes `<stateDir>/serve/phone-off` (`servectl.SetPhone`), which serve stats per request (`internal/serve/phone.go`): push muted, `remoteapproval.Guard` returns `ErrPhoneOff` (laptop popup only), every `Device`/`Write` route 503 `phone_off` (the app shows a "phone access is off" page), while `/a/` artifact routes (Public) keep working. Start removes it and bootstraps serve if the process is down (needs `serve install`); `serve stop --all` is the old `launchctl bootout` that keeps the plist (back at login). The 📱 badge is `on`/`off`/`down`/`stuck`. All launchctl/SIGTERM goes through injectable seams. Human-only: agents' Bash is denied these by the serve-tamper rules, and Write/Edit into the serve state dir by `serveEditTarget`.
- **cron/** — `agentctl cron` (scheduled runs): `schedules.json` jobs (global only), `robfig/cron` schedules, and the flock-guarded `cron tick` decisions (due fires with jitter, catch-up, overlap via windowstate `scheduled_by`, `max_concurrent`, usage gate, timeouts) behind injectable `Deps`; state and `runs.ndjson` under `<stateDir>/cron/`. The CLI and real deps (project binding, detached session start, dispatch through `cmd.DispatchOptions`) are in `internal/cmd/cron*.go`. See [docs/configuration.md](docs/configuration.md#cron).
- **cronedit/** — The one editing path for cron jobs, used by `cron add/edit/pause/resume/rm`, the `/v1/schedules` serve API and the hub's Schedules tabs (`T`, `internal/tui/fleet_schedules.go`/`fleet_schedform.go`/`fleet_schedgroup.go`: each project group with jobs gets `Sessions · Schedules M` header tabs, the selected tab (per project, `hubViewState.SchedTabs`) deciding whether the body lists agent rows or jobs, placed by longest symlink-resolved project-dir prefix, the rest in a collapsed bottom block; jobs load on hub start; card and form as a right-anchored drawer over the list pane that slides in on open (`schedDrawerTickMsg`, ~180ms ease-out, gen-guarded, closing is instant), the viewer pane never touched; agent check injected from `cmd/hub.go` as `dispatch.ValidateAgentName`, running windows via `WindowsFromRows`; writes and run-now as `tea.Cmd`s through the `fleetSchedStore`/`fleetSchedRun` seams): `Store` (seams for paths, clock, config, agent validation, `Options` = the model/backend/account sets: an unknown backend, account or Anthropic model is an error, a model outside an Ollama/Nous list a `Preview.Warnings` entry; `Preview.Diff` is the old → new change list; windows) with `Create`/`Update`/`Modify`/`SetEnabled`/`Delete` under a `<stateDir>/cron/jobs.lock` flock (the tick lock is taken inside it, and `last_fire` seeded before the save, only when the schedule changes or a job resumes), per-field `cron.FieldError`s, `Preview` (words, next 3 fires), `Detail` (card: next 3 fires, 20 runs, prompt_key text), `SimpleSchedule`/`ParseSimple` (picker model; exact round trip or Custom), `BuildOverview`/`SortForDisplay` (list status), and the run-now `RunFunc` seam whose production `RunSubprocess` runs `agentctl cron run --json` (stubbed in tests).
- **dispatchplan/** — Leaf below `internal/dispatch` (which imports `internal/hooks`): the dispatch precedence rules (`PermissionMode`, `Model`, `BackendName`, `AgentDir`, built-in agents) that `dispatch`/`cmd` call, and `Resolve`, which the approval hook uses to show where and how a gated dispatch will run (project dir, agent and its source, model, backend, harness, permission mode, worktree) without network or spawns. See "Remote approvals" in [docs/design/mobile-web-app.md](docs/design/mobile-web-app.md#remote-approvals).
- **agenthistory/** — Hidden git history of `~/.claude/agents`, `~/.claude/shared`, `~/.claude/CLAUDE.md` and `~/.claude/settings.json` (never other `~/.claude` content), a second store `<stateDir>/agent-history-config.git` for the agentctl global config dir (`config.json` and `templates/` only; `agents history|diff|revert --store agents|config|<project dir>`, or routed by an absolute path), and per project `<repo>/.claude/agents`, one store per root): a git dir at `<stateDir>/agent-history.git` (projects under `<stateDir>/agent-history/`), work tree the root, only the listed pathspecs staged (forced, since project agent dirs are gitignored), never a `.git` inside the tree. Every git call carries `--git-dir`/`--work-tree` through the `runGit` seam. `Snapshot(reason, author)` commits drift under a flock (files over 1 MB skipped, symlinks stored as links, git missing is a no-op with one warning); `reconcile.Housekeep` runs it behind the `agent-history.stamp` (5 min). `agentctl agents history|diff|revert`: revert is a new snapshot, and from an agent session goes through the approval popup (`agentsRevertPreviewGate`, `internal/hooks/agents_revert_preview.go`).
- **improverun/** — One improve run through the history stores (`<stateDir>/improve/<run-id>/{run.json,summary.md,report.md}`): `improve.Run` calls `Start` (snapshot of every store, reason `improve <id> start`) and exports `AGENTCTL_IMPROVE_RUN` (windowstate `ImproveRun`); the session writes its rationale to `summary.md` (path in the prompt). `Finish` (idempotent, flock) takes the end snapshot `improve <id>` with the rationale as commit body, records changed files and revisions in `run.json`, and when anything changed sends one desktop notification and publishes `report.md` as an artifact (serve pushes it to the phone, `serve.push.artifacts`); no change is a log line. Called from the Stop hook (turn end of an improve window), SessionEnd, `reconcile.Finish` (Gone) and housekeeping (`FinishStale`: a run is closed once older than 2h with its window gone, or after 12h whatever the window; `RecordWindow` stores the window, session and runtime dir, checked against tmux and windowstate `ImproveRun`), which also skips its own snapshot while a run is live. `CheckNoLiveRun` refuses a second improve run while one is live (they share the stores); `Prune` removes run dirs older than 90 days in housekeeping. `agentctl improve runs [--since]` lists them. `agentctl improve notify <run-id>` (hidden) re-sends a finished run's desktop notification and artifact (`improverun.Resend`) to re-test delivery; the detached `improve-finish` runs without the spawning session's `AGENTCTL_SESSION_ID`, so it logs to the shared `agentctl.log`.
- **prompttemplate/** — Leaf package for prompt templates (`agentctl template list|show|add|edit|rm`, `dispatch --template`): one Markdown file per template (yaml frontmatter `description`/`agent`/`model`/`dir`/`effort`, body = prompt) in `<config.GlobalDir()>/templates/` and `<project>/.agentctl/templates/` (project shadows global; the project root is worktree-aware). `Load`, `List`, `Save`, `Delete`, `Compose` (body plus `--prompt` under the "Additional instructions from the user" heading). Template values fill only unset dispatch flags (`applyDispatchTemplate` in `internal/cmd/dispatch.go`; `dispatchplan.Input.Template*`, source `template`). `template add/edit/rm` from an agent session always goes through the approval popup (`templatePreviewGate`, `internal/hooks/template_preview.go`, `PreviewKindTemplate`); the dispatch gate resolves `--template` from the payload `cwd` and fails closed (`resolveDispatchTemplate`). Direct writes to the templates dirs are denied (`checkTemplateTamper`, `templateEditTarget`). Cron jobs can run a fleet improve instead of a prompt (`Job.Mode` `improve`, `cron add|edit --improve-fleet`; `cron.Job.ImproveSince/ImproveSummary`, launched by `cmd.cronLaunchImprove` through `improve.Launch`, agent default `fleet-improver`, overlap `allow` refused). Cron jobs can name one (`Job.Template`, `cron add|edit --template`): resolved at fire time from the job dir through `applyDispatchTemplate` (`cronDispatchOptions`), a missing one recorded as `failed:template` and shown invalid by `cronedit.Store.Check`; the cron gate shows its prompt and denies an unresolvable `--template`. See [docs/configuration.md](docs/configuration.md#prompt-templates).
- **dispatchapproval/** — Single-use, 2-minute records that a human approved one `agentctl dispatch` in the popup (`Record` by the hook, `Consume` by the CLI), under `<stateDir>/dispatch-approvals/`; see "Gated commands" below.
- **launchd/** — LaunchAgent plist rendering and `launchctl` bootstrap/bootout, shared by `serve install` and `cron install`.
- **race/** — The pure model behind `agentctl race`: `Build` turns a transcript (via `logstream.ReadAll`) into steps (tool call + result, or text block; sidechain entries skipped) with agent time from timestamps (gaps capped at `MaxGap`, gaps ending at a human prompt not charged) and human time from runes typed (`TypedText`) and read at given WPMs; `AgentAt`/`HumanAt` place each racer on the timeline and `Playback` maps wall time to transcript time with no clock of its own. The TUI is `tui.RaceModel` (driven only by tick message times); the command, target resolution and `--json` are `internal/cmd/race.go`; `just demo-race` records the canned `testdata/demo.jsonl`.
- **sessionaudit/** — Pure leaf behind `agentctl audit report`: `Analyze` grades one transcript (race steps, merged with the session's `internal/audit` records by `tool_use_id`) against the table-driven safety/efficiency rules in `rules.go` (Bash parsed with `mvdan.cc/sh`), scores 100 minus severity weights, plus report-only metrics; the command, `--all` leaderboard and rendering are `internal/cmd/audit_report.go`, and `agentctl audit` with no subcommand is still the trail query (`audit log`). `audit report --narrate` adds a Nous verdict through `internal/auditnarrate` (findings and metrics only, prompt capped at ~6KB, cached per session by report hash under `<stateDir>/audit/narratives/`, ledgered as feature `audit`, honours the no-credits marker, never fatal). See [docs/permissions.md](docs/permissions.md#session-audit-reports).
- **artifacts/** — Leaf package: the machine-wide store of agent-published artifacts under `<stateDir>/artifacts/<id>/{meta.json,rev/<n>/}` (0700/0600, resolved lazily). `Add`/`Update` stage a copy under `.tmp` and rename it in, under a flock on `artifacts/.lock`, so a crash leaves no half artifact; kind and title inference (html/markdown/image/text), 20 revisions, limits (25 MB per revision, 500 files, 1 GB store), no symlinks followed, `Prune` skips pinned. The only writer is `agentctl artifact` (`internal/cmd/artifact.go`; direct Bash/Write/Edit are denied by `checkArtifactsTamper`/`artifactsEditTarget`), and `reconcile --housekeeping` prunes at 30 days. Every write touches `.changes/stamp`, which serve's `artifactWatcher` watches (SSE `artifact` events, the new-artifact push, `serve.push.artifacts`). `Open` (an `os.Root` on the revision dir, no symlink at any component) backs serve's content route: ids are 26 characters of base32 (130 bits) and are the viewing capability, so `/a/<id>/<rev>/<path>` serves them with no cookie (any browser on `allow_cidrs`, no pairing; `artifact add/url/open` print that direct link, plus the app link); a legacy 10-character id (`ValidID` accepts both, `CapabilityID` only the new form) still needs the device cookie, which only authenticates the entry request, redirected to the token URL `/a/t/<token>/<id>/<n>/<path>` (HMAC over id, rev, expiry, device; `internal/serve/artifact_token.go`), because browsers never send the cookie on a sandboxed document's subresources, and without the cookie it is the unknown-id 404; ids never reach the server log in full (`artifacts.ShortID`, `redactArtifactIDs`); every `/a/` response is sandboxed by a CSP (`artifact_content.go`, `routes_artifacts.go`). Design: [docs/design/artifacts.md](docs/design/artifacts.md).
- **demo/** — The screenshot harness behind `just demo`/`just demo-shot`: seeds a fake, isolated world (own tmux server `-L agentctl-demo`, temp HOME, fake repos, transcripts and canned panes) from a `demo/scenes/*.yaml` scene, writing records through `windowstate`, and generates the vhs tape from the scene's steps. Never linked into the agentctl binary. See [docs/development.md](docs/development.md#demo-harness-and-screenshots).
