# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

agentctl is a tmux-native command center for managing multiple coding agents: Claude Code by default, and pi (see `internal/harness`). It treats tmux as the runtime — each agent runs in its own window, Claude Code hooks write per-window state (working/blocked/idle) that a background monitor reads each tick.

## Build & Run

```bash
go build -o agentctl .    # build the binary
./agentctl                 # start or attach to the tmux session
go test ./...              # run the full test suite
golangci-lint run          # lint (config in .golangci.yml)
```

Tests live alongside the code — both at the repo root (`cli_test.go`, `monitor_test.go`, `smoke_test.go`, etc.) and throughout `internal/**`. Linter config is in `.golangci.yml`.

## Architecture

The binary is a single Go module (`github.com/blsmth/agentctl`). Subcommand routing uses [Kong](https://github.com/alecthomas/kong): the `CLI` struct in `cli.go` declares every subcommand and its `Run()` method. `main.go` runs a tiered bootstrap and dispatches Claude Code hook subcommands on a fast path before Kong.

### Root-level files (package main)

- **main.go** — Entry point, tiered init, hook fast-path, Kong dispatch, default session start/attach.
- **cli.go** — The Kong `CLI` struct: all subcommands (including hidden internal ones) and their `Run()` methods.
- **monitor.go** — Background monitor loop (headless Bubble Tea, 500ms tick). Reads hook-driven per-window state, resolves `AgentStatus`, parses JSONL for `state.json` token enrichment, renames tmux windows with state glyphs, and persists `state.json`.
- **birthtime_*.go** — Per-OS file birth-time helpers used for log-rotation (`/clear`) detection.

Most former root-level helpers now live under `internal/` (`internal/improve`, `internal/hooks`, `internal/cmd`, etc.).

### internal/ packages

- **tmux/** — All tmux interactions (sessions, windows, panes, keybindings, `display-popup`/`display-menu`). The per-window chrome bar (a two-row Bubble Tea pane docked at the bottom of each window) is gated by global config `chrome_bar` (default off, `chromegate.go`): off, the native tmux status line shows a plain window list; on, the status line is off and every window gets a bar. `LaunchChromeBar` reads the switch on each call (with it off it only records `main_pane`), and `agentctl apply-config` switches existing windows both ways. Session name is `tmux.SessionName` (`agentctl-<dir>`).
- **windowstate/** — Authoritative per-window hook state at `.agentctl/windows/<windowID>.json`. Written by hooks, read by the monitor.
- **winname/** — Computes the window name (glyph + instance) from windowstate and renames the tmux window inside the writer's transaction (`winname.Update`/`Transact`, `SyncName`).
- **state/** — The `state.json` snapshot the monitor writes each tick (agentctl readers build their view from `fleet.LoadAgents` and use a fresh snapshot only as optional token enrichment; also the one-release restore fallback), plus `AgentState`, the restore builders, and the snapshot types.
- **agent/** — Agent discovery from `~/.claude/agents/*.md` and project-local `.claude/agents/` (local shadows global); `Extends` composes agents.
- **sessions/** — Parses Claude Code's JSONL logs in every account's `projects/` dir (`~/.claude/projects/` by default) for summaries, metrics, and session metadata sidecars. Also owns session cost: `CostOfSummary` prices per request through `tokens.Lookup` (unknown model = unknown cost, never a Sonnet default) and `ClassifyBilling` assigns `metered`/`sub`/`free`; surfaced by `agentctl cost`. Pricing lives only in `internal/tokens`.
- **claudehome/** — Resolves Claude Code config dirs (`CLAUDE_CONFIG_DIR`), one per configured account: `Dir`, `All`, `Current`, and `Resolve` (flag > agent > `account_rules` on the repo root > dispatching window > `default_account`). Every transcript/settings path that used to hardcode `~/.claude` goes through it; shared content (agents, `settings.json`, …) still lives in `HomeDir()` and is symlinked into each account. agentctl never touches credentials (grep-tested). See [docs/configuration.md](docs/configuration.md#accounts-multiple-claude-logins).
- **config/** — Layered settings: project-local `.agentctl/config.json` over global `~/.config/agentctl/config.json`, reloaded every monitor tick. See [docs/configuration.md](docs/configuration.md); `internal/config` structs are the source of truth.
- **dispatch/**, **improve/** — `dispatch.RunComplete` (hook-spawned completion), plus dispatch/worktree orchestration; `improve.Run` starts a manual self-improvement session (never auto-triggered): `agentctl improve [<agent>] [--fleet] [--session] [--since] [--theme] [--template] [--model] [--backend] [--account] [--dry-run]` builds an evidence pack (`improve.Evidence`: closedlog outcome, audit denials/failures, cost, PR verdicts and session-audit findings through nil-able seams) into the prompt; the window opens unfocused unless started from the popup or hub (`LaunchSession`), records `spawned_by`, shows in the hub, and sweep closes it once idle; `cost --by agent` reports its spend as `improve:<agent>`.
- **harness/** — The agent program in a window: Claude Code (default) or pi. `Harness` owns everything program-specific: the launch command (fresh, restore, fork) and its env (`CLAUDE_CODE_*` lives in the Claude harness), `PrepareWorkspace` (Claude settings files through the launcher's writer; pi's embedded bridge extension `pi/agentctl-pi.ts`), hook payload decode to the canonical (Claude-shaped) payload plus output encoding (`EncodeDecision`), transcript location/parsing and pane classification. Callers check `Caps` (`NativeMessaging`, `Accounts`, `Backends`, `BlockedSignal`, ...) rather than names and degrade. Backends on pi: `dispatch.PrepareBackendFor` resolves and preflights them, and pi's `PrepareWorkspace` turns the `harness.Backend` into `AGENTCTL_PI_PROVIDER`, which the bridge registers (`Caps.RegistersBackends`). Selection: `dispatch --harness` > `agents.<name>.harness` (global-only) > frontmatter `harness:` > `claude`; recorded in windowstate/`restore.json` (empty = claude) and `AGENTCTL_HARNESS`. Every launch path (`dispatch.Launch`, `dispatch.Restore`, `improve.LaunchSession`, `cmd.LaunchWithResume`) goes through it; the Claude golden tests (`testdata/golden`, via `internal/tmux/launchtest`) pin its command lines and env. See [docs/configuration.md](docs/configuration.md#harnesses-claude-code-and-pi).
- **transcript/** — Leaf package normalizing non-Claude transcript records (pi session files) into Claude Code's JSONL shape; `logstream`, `sessions` and the HUD apply it per line, so tokens, cost and summaries work on any harness.
- **hooks/** — Claude Code hook handlers (`hooks.Dispatch`): write windowstate, fire notifications, validate Bash, derive done state. Harnesses other than Claude call them with `--harness <name>` (`hooks.SetHarness`): stdin decodes through `harness.DecodeHook` and decisions go out through `emitDecision`; the state logic is shared.
- **tui/** — Bubble Tea models: the fsnotify-fed chrome bar, menus, wizards, and full-screen browsers; the hub's `/` type-to-search filter (`fleet_search.go`).
- **render/** — Leaf package of presentation helpers shared by the chrome bar and the statusline so both render the same numbers.
- **statusline/** — Handles `agentctl statusline`, the command Claude Code pushes its JSON payload to (fast path before Kong). Renders `rich`, `complementary`, `full`, `mobile` (two phone-width lines: model/ctx/session length, 5h/7d/cost/account; `mobile_render.go`), or `minimal` per `statusline_format` and records pushed rate-limit and context data. Git branch is read from `.git/HEAD` with no subprocess; only the dirty count shells out, under a 150ms timeout. While `agentctl serve` has a live phone terminal or an open window detail screen on the window (marker in `<stateDir>/phone-viewed/`, `internal/phoneview`) and no laptop client views it, it renders `statusline_mobile_format` (default `mobile`); `tmux list-clients` runs only when a marker exists. Right-alignment (`statusline_align`) pads with U+2800 because Claude Code strips leading whitespace; see `padRune` and `rightAlignReserve` in `statusline.go`.
- **llm/** — Single-turn `llm.Completer` keyed on `llm.provider` (`ollama`, `claude`; empty = disabled). The Ollama client always sends `think:false`, sets `num_ctx`, and errors rather than return a blank or truncated completion. Consumers: the work journal, and `NousClient` (OpenAI-compatible chat completions on a `nous` backend, content only, never reasoning) for short titles; every failure is non-fatal. `NousClient` implements the optional `llm.UsageReporter` (usage from the response) and appends every call, failed ones too, to the `internal/llmusage` ledger (`<stateDir>/llm-usage/usage-<YYYY-MM>.ndjson`, attributed by `llmusage.WithMeta` in the context, priced at write time, `cost_usd` null when unknown, pruned at 90 days by housekeeping); `agentctl cost` reports it in its own Background LLM calls section, never in session totals.
- **shorttitle/** — 2-5 word row titles (`fleet.RecapLine.Title`, served as `title`), config `titles` (global-only). Generated by the async `hook-title` on Stop/UserPromptSubmit/SessionStart from the task or ticket (a bare window's first prompt, stored as windowstate `first_prompt`); the reply is `<kind> | <title>` (closed kind set, stored as `short_title.kind`, not drawn itself; review-pr windows are always `review`). A sub-agent window (`spawned_by` and `spawned_by_session` both set) gets its parent's row title as a prompt hint (`Input.ParentTitle`, not in `Hash`; `titleInput`/`parentTitle` in `internal/hooks/title.go`, same-runtime-dir lookup only, so `BackfillTitles` gets it too) so its title names its own piece, not the orchestrator's, and a role label from `shorttitle.Role(mode, kind)` (`review`/`research`/`fix`/`docs`/`tests`/`build`; `fleet.Row.ShortRole`, served as `role`), shown before the title on hub child rows and as the pill on the phone, never on bare/cron rows; stored in windowstate `short_title`, so readers never touch the network. At most two titles per window: the first, then one refinement at the first Stop from that response, after which `short_title.final` freezes it (no time-based or away_summary retitle; `/clear` resets it, resume/compact do not). Failures keep the title unfrozen under a retry backoff, a machine-wide hourly cap (`titles.hourly_cap`, default 120, `<stateDir>/titles/budget.json`; resume/compact SessionStart requests cannot take the last 30 slots, so a restore burst never starves new sessions), and an in-transaction claim so a double-registered hook sends one request. Windows no hook reaches (idle since before titles) are backfilled by `reconcile --housekeeping` (`hooks.BackfillTitles`, wired in `internal/cmd/reconcile.go`): live windows of this session only, at most 3 per 5-minute run, leaving 40 of the hourly cap to the hooks (30 for new sessions plus 10), final once the window has finished a turn. Untitled rows show the recap's first sentence, cut at a word boundary (`fleet.TruncateWords`, `truncateWords` on the phone). A human can rename a row from the hub (`R`, the row menu, or double-click its title; `internal/tui/fleet_rename.go`): `shorttitle.SetManual` writes `short_title` with `manual` (and `final`) through `windowstate.UpdateIn` in the row's own runtime dir (never creates a record). Manual titles are never replaced: `shorttitle.Due`/`Apply`, `hook-title`, `BackfillTitles` and the `/clear` reset all skip them, and fleet shows them whatever the recap source (`Row.ShortManual`). An empty save clears `short_title` so automatic titles resume. Each request is ledgered with feature `titles`, the window and its project. When `hook-title` runs it also refreshes the machine-wide price cache if it is over 24h old (`pricecache.RefreshIfStale`, once a day machine-wide, silent). No spawns; never uses the `claude` CLI. See [docs/configuration.md](docs/configuration.md#titles).
- **closedlog/** — Machine-wide NDJSON ledger of closed agent windows (`<stateDir>/closed/closed-<YYYY-MM>.ndjson`): `reconcile.Finish` appends one line per tracked window (shell/unidentifiable skipped, non-fatal, one `O_APPEND` write), with `reason` `cascade` for `close_children` kills (windowstate `closed_by`, set by the cascade before the kill) and `improve` for `agentctl improve` windows (windowstate Mode `improve`). `Load(since)` is newest first, deduped by `Key`, corrupt lines skipped; `Cache` re-reads on file change; housekeeping prunes at 90 days. Read by `agentctl status list --closed` and the hub's `C` Closed section, whose Enter resumes through the hidden `agentctl hub-resume` (`cmd.launchResume`, the `LaunchWithResume` path). Session teardown never reaches it.
- **pricecache/**, **llmusage/** — `pricecache` writes/fetches/refreshes the machine-wide Nous catalog copy under `<stateDir>/pricing` (`Refresh`, once-a-day `RefreshIfStale`); `llmusage` is the NDJSON ledger of agentctl's own LLM calls (`Append`, `Load`, `Prune`, `Cost`). Both resolve state paths lazily and are covered by `testenv` TestMains.
- **verdicts/** — Machine-wide NDJSON ledger of PR review verdicts (`<stateDir>/verdicts/verdicts-<YYYY-MM>.ndjson`, pruned at 90 days by housekeeping). The PostToolUse hook (`hooks.recordVerdict`, only for the `SendMessage` tool, one substring check first) appends a line when the body matches `REVIEW PR #N — VERDICT: MERGE|MERGE-WITH-FOLLOWUPS|BLOCKED|NEEDS-BRENDAN`; the author comes first from the reviewer's own windowstate `review` (`windowstate.ReviewTarget`: PR, head branch, repo, author window/agent/session/runtime dir, recorded by `dispatch --review-pr`), else the live window in the runtime dir whose windowstate records that PR (`pr_number`/`log_pr`), never a `gh` call, so unresolved authors are left empty. `ByAuthor` counts one verdict per (PR, reviewer session), the latest. Only a message that starts with the verdict line counts (a relayed quote does not); `Rounds: N` is parsed. The author is the window whose dispatch completion recorded the PR, else one whose transcript linked it (never a `review-pr` window; ties by lowest window ID). Read by `agentctl audit verdicts [--since 30d] [--json]` (a sibling of `audit log` and `audit report`; BLOCKED rate per author agent). `sessionaudit` ignores `tool_approved` records when merging and labels `denied_by: timeout` as an unanswered popup. Approval popups also write audit events: a timeout is `tool_denied` with `denied_by: "timeout"` (older records say `rule`), an approval is `tool_approved` with `source` `laptop|phone` and `duration_ms`.
- **claude/** — Persistent `claude` CLI subprocess client (NDJSON over stdio), retained as a non-default `llm` provider selectable only with `llm.provider: "claude"`. Kept deliberately as the basis for any future Go agent integration.
- **worktree/** — Git worktree create/remove/list/prune for isolated dispatch, under `<repo>/.worktrees/<slug>/`.
- **cleanup/** — Classifies worktrees (`empty`, `landed`, dirty, unpushed, …) so `agentctl cleanup` and SessionEnd reclaim only what is safe.
- **fleet/** — Cross-session aggregation behind `agentctl hub` and `agentctl status`, including pane classification (`ClassifyPane`).
- **mailbox/** — Per-window store for agentctl-originated notices (done/blocked backstop), delivered by the UserPromptSubmit/PostToolUse hooks. Agent-to-agent messaging is Claude Code's native `SendMessage`/`ListAgents`, not this package.
- **metrics/**, **metricsserve/**, **metricsproc/** — Prometheus registry, collectors and remote write; `metrics/events` is the hook-written transition log; `metricsserve` is `agentctl metrics serve`; `metricsproc` is its pidfile/lock/start plumbing. See [docs/monitor-architecture.md](docs/monitor-architecture.md#metrics-without-the-monitor).
- **notify/** — Desktop notifications from `notify_cmd` (`alerter` on macOS, `notify-send` on Linux).
- **serve/** — `agentctl serve`, the per-machine HTTPS server for the mobile web app: local CA + leaf certs, CIDR filter, device-cookie auth, CSRF, pairing over a 0600 control socket. Routes register through `Router` (`Public`/`Device`/`Write`); see [docs/design/mobile-web-app.md](docs/design/mobile-web-app.md). Start/stop live in the leaf `internal/servectl` (`serve start|stop|toggle`, prefix+`W`, the hub's `📱` indicator and `S` key) and switch phone access, not the process: stop writes `<stateDir>/serve/phone-off` (`servectl.SetPhone`), which serve stats per request (`internal/serve/phone.go`): push muted, `remoteapproval.Guard` returns `ErrPhoneOff` (laptop popup only), every `Device`/`Write` route 503 `phone_off` (the app shows a "phone access is off" page), while `/a/` artifact routes (Public) keep working. Start removes it and bootstraps serve if the process is down (needs `serve install`); `serve stop --all` is the old `launchctl bootout` that keeps the plist (back at login). The 📱 badge is `on`/`off`/`down`/`stuck`. All launchctl/SIGTERM goes through injectable seams. Human-only: agents' Bash is denied these by the serve-tamper rules, and Write/Edit into the serve state dir by `serveEditTarget`.
- **cron/** — `agentctl cron` (scheduled runs): `schedules.json` jobs (global only), `robfig/cron` schedules, and the flock-guarded `cron tick` decisions (due fires with jitter, catch-up, overlap via windowstate `scheduled_by`, `max_concurrent`, usage gate, timeouts) behind injectable `Deps`; state and `runs.ndjson` under `<stateDir>/cron/`. The CLI and real deps (project binding, detached session start, dispatch through `cmd.DispatchOptions`) are in `internal/cmd/cron*.go`. See [docs/configuration.md](docs/configuration.md#cron).
- **cronedit/** — The one editing path for cron jobs, used by `cron add/edit/pause/resume/rm`, the `/v1/schedules` serve API and the hub's Schedules tabs (`T`, `internal/tui/fleet_schedules.go`/`fleet_schedform.go`/`fleet_schedgroup.go`: each project group with jobs gets `Sessions · Schedules M` header tabs, the selected tab (per project, `hubViewState.SchedTabs`) deciding whether the body lists agent rows or jobs, placed by longest symlink-resolved project-dir prefix, the rest in a collapsed bottom block; jobs load on hub start; card and form as a right-anchored drawer over the list pane that slides in on open (`schedDrawerTickMsg`, ~180ms ease-out, gen-guarded, closing is instant), the viewer pane never touched; agent check injected from `cmd/hub.go` as `dispatch.ValidateAgentName`, running windows via `WindowsFromRows`; writes and run-now as `tea.Cmd`s through the `fleetSchedStore`/`fleetSchedRun` seams): `Store` (seams for paths, clock, config, agent validation, `Options` = the model/backend/account sets: an unknown backend, account or Anthropic model is an error, a model outside an Ollama/Nous list a `Preview.Warnings` entry; `Preview.Diff` is the old → new change list; windows) with `Create`/`Update`/`Modify`/`SetEnabled`/`Delete` under a `<stateDir>/cron/jobs.lock` flock (the tick lock is taken inside it, and `last_fire` seeded before the save, only when the schedule changes or a job resumes), per-field `cron.FieldError`s, `Preview` (words, next 3 fires), `Detail` (card: next 3 fires, 20 runs, prompt_key text), `SimpleSchedule`/`ParseSimple` (picker model; exact round trip or Custom), `BuildOverview`/`SortForDisplay` (list status), and the run-now `RunFunc` seam whose production `RunSubprocess` runs `agentctl cron run --json` (stubbed in tests).
- **dispatchplan/** — Leaf below `internal/dispatch` (which imports `internal/hooks`): the dispatch precedence rules (`PermissionMode`, `Model`, `BackendName`, `AgentDir`, built-in agents) that `dispatch`/`cmd` call, and `Resolve`, which the approval hook uses to show where and how a gated dispatch will run (project dir, agent and its source, model, backend, harness, permission mode, worktree) without network or spawns. See "Remote approvals" in [docs/design/mobile-web-app.md](docs/design/mobile-web-app.md#remote-approvals).
- **agenthistory/** — Hidden git history of `~/.claude/agents`, `~/.claude/shared`, `~/.claude/CLAUDE.md` and `~/.claude/settings.json` (never other `~/.claude` content), a second store `<stateDir>/agent-history-config.git` for the agentctl global config dir (`config.json` and `templates/` only; `agents history|diff|revert --store agents|config|<project dir>`, or routed by an absolute path), and per project `<repo>/.claude/agents`, one store per root): a git dir at `<stateDir>/agent-history.git` (projects under `<stateDir>/agent-history/`), work tree the root, only the listed pathspecs staged (forced, since project agent dirs are gitignored), never a `.git` inside the tree. Every git call carries `--git-dir`/`--work-tree` through the `runGit` seam. `Snapshot(reason, author)` commits drift under a flock (files over 1 MB skipped, symlinks stored as links, git missing is a no-op with one warning); `reconcile.Housekeep` runs it behind the `agent-history.stamp` (5 min). `agentctl agents history|diff|revert`: revert is a new snapshot, and from an agent session goes through the approval popup (`agentsRevertPreviewGate`, `internal/hooks/agents_revert_preview.go`).
- **improverun/** — One improve run through the history stores (`<stateDir>/improve/<run-id>/{run.json,summary.md,report.md}`): `improve.Run` calls `Start` (snapshot of every store, reason `improve <id> start`) and exports `AGENTCTL_IMPROVE_RUN` (windowstate `ImproveRun`); the session writes its rationale to `summary.md` (path in the prompt). `Finish` (idempotent, flock) takes the end snapshot `improve <id>` with the rationale as commit body, records changed files and revisions in `run.json`, and when anything changed sends one desktop notification and publishes `report.md` as an artifact (serve pushes it to the phone, `serve.push.artifacts`); no change is a log line. Called from the Stop hook (turn end of an improve window), SessionEnd, `reconcile.Finish` (Gone) and housekeeping (`FinishStale`: a run is closed once older than 2h with its window gone, or after 12h whatever the window; `RecordWindow` stores the window, session and runtime dir, checked against tmux and windowstate `ImproveRun`), which also skips its own snapshot while a run is live. `CheckNoLiveRun` refuses a second improve run while one is live (they share the stores); `Prune` removes run dirs older than 90 days in housekeeping. `agentctl improve runs [--since]` lists them.
- **prompttemplate/** — Leaf package for prompt templates (`agentctl template list|show|add|edit|rm`, `dispatch --template`): one Markdown file per template (yaml frontmatter `description`/`agent`/`model`/`dir`/`effort`, body = prompt) in `<config.GlobalDir()>/templates/` and `<project>/.agentctl/templates/` (project shadows global; the project root is worktree-aware). `Load`, `List`, `Save`, `Delete`, `Compose` (body plus `--prompt` under the "Additional instructions from the user" heading). Template values fill only unset dispatch flags (`applyDispatchTemplate` in `internal/cmd/dispatch.go`; `dispatchplan.Input.Template*`, source `template`). `template add/edit/rm` from an agent session always goes through the approval popup (`templatePreviewGate`, `internal/hooks/template_preview.go`, `PreviewKindTemplate`); the dispatch gate resolves `--template` from the payload `cwd` and fails closed (`resolveDispatchTemplate`). Direct writes to the templates dirs are denied (`checkTemplateTamper`, `templateEditTarget`). The hub's new-session prompt offers them too (`internal/tui/fleet_newsession_tmpl.go`, launching through `hub-new-session --template`). Cron jobs can run a fleet improve instead of a prompt (`Job.Mode` `improve`, `cron add|edit --improve-fleet`; `cron.Job.ImproveSince/ImproveSummary`, launched by `cmd.cronLaunchImprove` through `improve.Launch`, agent default `fleet-improver`, overlap `allow` refused). Cron jobs can name one (`Job.Template`, `cron add|edit --template`): resolved at fire time from the job dir through `applyDispatchTemplate` (`cronDispatchOptions`), a missing one recorded as `failed:template` and shown invalid by `cronedit.Store.Check`; the cron gate shows its prompt and denies an unresolvable `--template`. See [docs/configuration.md](docs/configuration.md#prompt-templates).
- **dispatchapproval/** — Single-use, 2-minute records that a human approved one `agentctl dispatch` in the popup (`Record` by the hook, `Consume` by the CLI), under `<stateDir>/dispatch-approvals/`; see "Gated commands" below.
- **launchd/** — LaunchAgent plist rendering and `launchctl` bootstrap/bootout, shared by `serve install` and `cron install`.
- **race/** — The pure model behind `agentctl race`: `Build` turns a transcript (via `logstream.ReadAll`) into steps (tool call + result, or text block; sidechain entries skipped) with agent time from timestamps (gaps capped at `MaxGap`, gaps ending at a human prompt not charged) and human time from runes typed (`TypedText`) and read at given WPMs; `AgentAt`/`HumanAt` place each racer on the timeline and `Playback` maps wall time to transcript time with no clock of its own. The TUI is `tui.RaceModel` (driven only by tick message times); the command, target resolution and `--json` are `internal/cmd/race.go`; `just demo-race` records the canned `testdata/demo.jsonl`.
- **sessionaudit/** — Pure leaf behind `agentctl audit report`: `Analyze` grades one transcript (race steps, merged with the session's `internal/audit` records by `tool_use_id`) against the table-driven safety/efficiency rules in `rules.go` (Bash parsed with `mvdan.cc/sh`), scores 100 minus severity weights, plus report-only metrics; the command, `--all` leaderboard and rendering are `internal/cmd/audit_report.go`, and `agentctl audit` with no subcommand is still the trail query (`audit log`). `audit report --narrate` adds a Nous verdict through `internal/auditnarrate` (findings and metrics only, prompt capped at ~6KB, cached per session by report hash under `<stateDir>/audit/narratives/`, ledgered as feature `audit`, honours the no-credits marker, never fatal). See [docs/permissions.md](docs/permissions.md#session-audit-reports).
- **artifacts/** — Leaf package: the machine-wide store of agent-published artifacts under `<stateDir>/artifacts/<id>/{meta.json,rev/<n>/}` (0700/0600, resolved lazily). `Add`/`Update` stage a copy under `.tmp` and rename it in, under a flock on `artifacts/.lock`, so a crash leaves no half artifact; kind and title inference (html/markdown/image/text), 20 revisions, limits (25 MB per revision, 500 files, 1 GB store), no symlinks followed, `Prune` skips pinned. The only writer is `agentctl artifact` (`internal/cmd/artifact.go`; direct Bash/Write/Edit are denied by `checkArtifactsTamper`/`artifactsEditTarget`), and `reconcile --housekeeping` prunes at 30 days. Every write touches `.changes/stamp`, which serve's `artifactWatcher` watches (SSE `artifact` events, the new-artifact push, `serve.push.artifacts`). `Open` (an `os.Root` on the revision dir, no symlink at any component) backs serve's content route: ids are 26 characters of base32 (130 bits) and are the viewing capability, so `/a/<id>/<rev>/<path>` serves them with no cookie (any browser on `allow_cidrs`, no pairing; `artifact add/url/open` print that direct link, plus the app link); a legacy 10-character id (`ValidID` accepts both, `CapabilityID` only the new form) still needs the device cookie, which only authenticates the entry request, redirected to the token URL `/a/t/<token>/<id>/<n>/<path>` (HMAC over id, rev, expiry, device; `internal/serve/artifact_token.go`), because browsers never send the cookie on a sandboxed document's subresources, and without the cookie it is the unknown-id 404; ids never reach the server log in full (`artifacts.ShortID`, `redactArtifactIDs`); every `/a/` response is sandboxed by a CSP (`artifact_content.go`, `routes_artifacts.go`). Design: [docs/design/artifacts.md](docs/design/artifacts.md).
- **demo/** — The screenshot harness behind `just demo`/`just demo-shot`: seeds a fake, isolated world (own tmux server `-L agentctl-demo`, temp HOME, fake repos, transcripts and canned panes) from a `demo/scenes/*.yaml` scene, writing records through `windowstate`, and generates the vhs tape from the scene's steps. Never linked into the agentctl binary. See [docs/development.md](docs/development.md#demo-harness-and-screenshots).

### Behavior notes

- **Monitor hot reload**: monitor-side changes go live within about one tick of `just install`, with no relaunch needed. The monitor records its binary identity in `<runtimeDir>/monitor.build` and re-execs itself (same PID) when the file changes (`monitor_reexec.go`); the hook watchdog replaces older monitors that never wrote that file. In-memory state resets on re-exec (see [docs/monitor-architecture.md](docs/monitor-architecture.md#hot-reload)). The hub list (`hub-view`) hot-reloads too: on its poll tick it quits cleanly when the binary changes, then execs the new one, passing the selection via `AGENTCTL_HUB_SELECT` and the fold/filter state via `AGENTCTL_HUB_VIEW` (also persisted in `<stateDir>/hub-view.json`). The per-window chrome bar and HUD panes, and the hub's status pane (`hub-status`, above the live viewer; see [docs/design/fleet-view-design.md](docs/design/fleet-view-design.md#live-agent-pane)), hot-reload the same way (3s check, 0-2s per-window jitter, quit then exec; a failed exec keeps the old image running). Shared logic lives in `internal/selfexec`.
- **Notifications** are hook-driven (`internal/hooks/`), not monitor-driven. Settings: see [docs/configuration.md](docs/configuration.md#notifications).
- **Auto-opening PRs**: when a dispatched agent finishes with a PR, completion runs from the Stop hook (or `agentctl signal done`), not the monitor: it spawns a detached `agentctl dispatch-complete <window>` that opens the PR via `gh pr view --web` (config `open_pr_in_browser`), once per PR, deduped across processes by marker files in `<runtimeDir>/opened-prs/`.
- **Worktree reclaim on SessionEnd**: on a terminal `SessionEnd` the hook runs `cleanup.Classify` against the window's own worktree and reclaims it (with its window) only when the verdict is `empty` or `landed`. `git worktree prune` always runs. Opt out with `auto_reclaim_worktree: false`.
- **Gated commands**: `agentctl cron add`, `cron edit` (the popup shows the job after the edit and the changed fields), `cron resume`, `cron run --force` (`cronPreviewGate`, `internal/hooks/cron_preview.go`, `PreviewKindCron`) always go through the approval popup, independent of `bash_preview`; plain `cron run` and the read-only cron subcommands do not. `agentctl dispatch` (`dispatchPreviewGate`, behind the `dispatchGate` seam) is gated per the global `dispatch_approval` key (`dispatchNeedsApproval`): `all`, `non-review` (default: every dispatch except a literal positive `--review-pr N` whose agent resolves to `code-reviewer` (`config.DefaultReviewAgent`: no `--agent`/`-a`, or a last one naming it) and whose other flags are all in `reviewExemptValueFlags`/`reviewExemptBoolFlags` (`--prompt` focus allowed; `--issue`/`--dir`/`--backend`/... are not), which the popup shows as a "Review PR #N" row when gated; a review by any other agent, or a line with any non-exempt dispatch, stays gated; the exemption also needs `code-reviewer` to resolve to the global registry file (`agent.ResolvesGlobal`: a regular file in `~/.claude/agents/`, `os.SameFile`, no project-local shadow or local `extends` base) from the payload `cwd` and a line where only `agentctl` commands precede each dispatch (`reviewExemptionTrusted`/`lineChangesContext`, `internal/hooks/dispatch_approval_marker.go`); the CLI backstop is `reviewerGate` in `internal/cmd/dispatch_review.go`, which, for an agent-session caller under a non-`off` mode, refuses a local reviewer (checked before launch and again in the worktree via `dispatch.Request.VerifyAgent`) unless the single-use, 2-minute `internal/dispatchapproval` marker that the hook writes to `<stateDir>/dispatch-approvals/` (keyed by window + SHA-256 of the dispatch args) when a human approves a dispatch popup was consumed on its first check, whatever the reviewer resolved to; plain-shell humans are never refused), or `off`; unknown values mean `all`, and a project config may tighten but never loosen it. Agents cannot loosen the global value: `globalConfigEditTarget` (`internal/hooks/config_guard.go`, `hook-pre-tool`) denies a Write/Edit/MultiEdit of `config.GlobalFilePath` whose result is less strict, and `checkConfigTamper` denies Bash writes to that file and any command mentioning `dispatch_approval` with it. An exempted dispatch is an ordinary Bash command (`bash_preview` still applies); the dispatch+cron mix deny stays. Both gates fail closed when the prompt cannot be shown (unresolvable `--prompt-key`; for cron also `$`/backtick values and unreadable `--prompt-file`). Direct writes to `schedules.json` and `<stateDir>/cron/` are denied (`checkCronTamper` for Bash, `cronEditTarget` in `hook-pre-tool` for Write/Edit), and so are writes to `<stateDir>/dispatch-approvals/` (`checkApprovalTamper`, `approvalEditTarget`), a speed bump like the serve-tamper rules. The Bash tamper rules (cron, template, approval, artifacts, config and serve) ignore the argument words of `agentctl` commands (`maskAgentctlArgs`, `internal/hooks/agentctl_args.go`; single quotes are literal, `#` is a comment only at a word start outside quotes) unless that command has a command substitution outside single quotes, or the line has syntax the scanner does not model (`$'`, `${`, unterminated quote). The serve rule checks real `agentctl serve <sub>` invocations by their words (`agentctlServeTamper`), including inside an unquoted `$(...)`. The shared write matcher (`matchesWriteTemplates`) also matches each command restated with earlier `cd`s (`cdCertain`; an uncertain cd adds a candidate dir), shell variables and `bash -c`/`eval` scripts resolved (`writeViews`, `internal/hooks/write_views.go`), and denies `find <dir> -delete|-exec|...` and `... | xargs <write verb>`. Running agentctl from source is denied by `checkGoRunAgentctl` (`internal/hooks/gorun.go`, tokenized, command-position words only): a `go run` of the agentctl root main package (`.`, root `.go` files, `github.com/blsmth/agentctl[@v]`, or a path whose `go.mod` declares that module, resolved from the payload `cwd` plus leading `cd`/`-C`; unresolvable `.` denies only when the line mentions agentctl), while `go run ./internal/...` and other repos pass. The same detection makes the dispatch and cron gates and the serve-tamper rule treat `go run <root pkg> [--] dispatch|cron <sub>|serve <sub>` as the agentctl command (`rewriteGoRunAgentctl` in `invocationTokens`, `scanGate` mode: a `go [-C dir] run` anywhere in a simple command counts, behind wrappers like `timeout`/`xargs` too, and `cd` is ignored, so `.` always counts as agentctl; the deny rule (`scanDeny`) follows `cd` only when it surely runs in the outer shell, `cdCertain`, and undoes a subshell's `cd` at its closing paren), and such a review dispatch never gets the review exemption. A renamed built binary (`go build -o /tmp/x . && /tmp/x dispatch`) is not caught.
- **`bash_preview`**: `bashPreviewGate` (`internal/hooks/preview_gate.go`) only shows the popup when a human is attached **and** looking at the issuing window (`tmuxHasAttachedClient`); otherwise the command passes through. That backstop prevents unattended dispatches from deadlocking on an invisible popup. Unanswered popups (dispatch, cron and bash) deny after a deadline (`popupDeadline`, 9m against the 600s `timeout` registered on `hook-validate-bash`) and the popup is closed with `tmux display-popup -C`, rather than failing open when Claude Code kills the hook. While a popup is open the window is marked `blocked` (PendingTool `dispatch`/`cron`/`Bash`) with a desktop notification (`approval_pending`, gated by `alert_config.blocked`) and a marker file in `<runtimeDir>/approval-pending/` that makes the monitor defer `gh pr view --web` auto-open (up to ~2 minutes, then skip). State is restored to `working` on every exit path. When `agentctl serve` is running (and its control socket passes `remoteapproval.Guard`), the same approval is also offered to the phone and the first answer wins; with no laptop client the phone alone answers. See "Remote approvals" in [docs/design/mobile-web-app.md](docs/design/mobile-web-app.md#remote-approvals).
- **Cost**: one pricing source, `internal/tokens` (config overrides, then the cached Nous catalog, then built-ins, then newest-generation family fallback). The catalog is read from the runtime-dir `nous-models-*.json` and the machine-wide `<stateDir>/pricing/nous-*.json` (`internal/pricecache`, written on every fetch, any age is fine for pricing); `agentctl cost prices [filter] [--refresh]` shows the resolved price and source per model. Tiered models (Haiku 5.5) are priced per request, so session totals are summed per turn, and the parser dedups JSONL lines by `message.id`. The statusline hides Claude Code's pushed `total_cost_usd` for non-`claude-*` models. See [docs/configuration.md](docs/configuration.md#pricing-and-cost).
- **Accounts** (`accounts`, `default_account`, `account_rules`, `agents.*.account`, global-only; `dispatch --account`, `agentctl account add/list/doctor/rm`): each launch path sets `CLAUDE_CONFIG_DIR` for the resolved account (unsets it for `~/.claude`, via `claudehome.EnvFor`: an explicit default dir is a different, logged-out login) and scrubs inherited credential env vars; the account is recorded in windowstate/restore.json. Accounts never message each other: a cross-account worker gets no orchestrator section. No automatic failover between accounts.
- **Backends** (Ollama and Nous Portal via `backends` + `agents.*.backend`, global-only; `dispatch --backend`): `nous` delivers its API key through `apiKeyHelper` (`agentctl backend-token`), never through env or config. See [docs/configuration.md](docs/configuration.md#backends-ollama-and-nous-portal).
- **Session restore** reads `<runtimeDir>/restore.json`, built from per-window `windowstate` records at every point that destroys windows (`StartSession` before `RemoveAll`, `tmux.KillSession`, relaunch-prep, `save-state`), not from the monitor's `state.json`. `state.json` is only a one-release fallback when `restore.json` is absent. See [docs/monitor-architecture.md](docs/monitor-architecture.md#session-restore-restorejson).
- **Folder-trust prompt**: Claude Code asks to trust a new folder (every fresh worktree) before it loads hooks, so no hook can report it. Each launch path calls `launchwatch.Start` (only for `Caps.TrustDialog` harnesses), which spawns the hidden, detached `agentctl launch-watch <window>` (`hooks.LaunchWatch`): it reads the pane about once a second for up to 90s, stops once the window has a `SessionID`, and on `panestate.IsTrustDialog` marks the window `blocked` with PendingTool `trust` (`windowstate.PendingTrust`, folder as the detail; shown as "folder trust" via `fleet.PendingLabel`), notifies (`alert_config.blocked`) and mails the dispatcher an `agentctl notice:`, once. SessionStart/UserPromptSubmit clear it (`windowstate.ClearPendingTrust`). It never answers the dialog. Tests stub the spawn (`launchwatch.SetSpawnForTest`, `launchtest.Capture`). See [docs/monitor-architecture.md](docs/monitor-architecture.md#before-the-first-hook-the-launch-watcher).
- **Gone and housekeeping without the monitor**: hidden `agentctl reconcile` (flock-guarded, idempotent) claims records of vanished windows and fires the Gone handlers once. It is spawned detached after `tmux.KillWindow`/SessionEnd kills, run by a session `window-unlinked` tmux hook, and spawned by a 60s-stamped janitor on SessionStart/UserPromptSubmit (`--housekeeping` adds orphan reaping, mailbox/session-log pruning, approval-marker GC). `client-resized`/`client-attached`/`client-session-changed` hooks run `enforce-chrome` (which also undoes hub chrome-hiding zooms the hub no longer needs). `agentctl apply-config` re-applies hooks and keybindings to a live session. See [docs/monitor-architecture.md](docs/monitor-architecture.md#gone-and-housekeeping-without-the-monitor).
- **Closing a window closes its children** (`close_children`, global-only, default true): `reconcile.Finish` closes live windows (any agentctl session) whose `spawned_by` **and** `spawned_by_session` match the gone record, via `tmux.KillWindowIn`; grandchildren cascade through each child's own reconcile. Never on session teardown (`HasSession` false), for a window saved in `restore.json`, or when a live window still carries the parent's `SessionID` (restored). Cron/detached windows are never targets; worktrees are never deleted by it. The kill popup names the sessions it will also close. See [docs/monitor-architecture.md](docs/monitor-architecture.md#gone-and-housekeeping-without-the-monitor).
- **Monitor kill switch**: global config `monitor: false` (default true) stops session start / `applyConfig` and the hook watchdog from starting or replacing a monitor, and `agentctl health` reports "monitor disabled". A running monitor is never killed by the flag. Like `cross_context`, a project may switch it off but never back on.
- **Command-type config keys** (`notify_cmd`, `hooks.*`, `dispatch.on_complete`) are read only from the global config, never from project-local `.agentctl/config.json`.

### Key data flow

1. `agentctl` starts a tmux session → runs the monitor as a background process (pidfile-guarded)
2. Claude Code hooks write per-window state to `.agentctl/windows/<windowID>.json` (`working`/`blocked`/`idle`)
3. Monitor loops every 500ms, reads each window's hook state, and resolves it to an `AgentStatus`; `Gone` is detected when a window disappears (monitor after two absent ticks, or the monitor-free `agentctl reconcile` via the shared `internal/reconcile` claim). JSONL is parsed only for token/detail enrichment. Readers (chrome bar, hub, `status`, popups) do not depend on it: they join `tmux list-windows` with `windowstate.AllFrom` via `fleet.LoadAgents`. Config `monitor: false` stops agentctl starting it.
4. On a state change the monitor builds a `Transition` and calls `fireHandlers` (no handler is registered today, and there is no plugin registry). Prometheus metrics are not a monitor handler: the state writers (`winname.Apply`, `reconcile.Finish`) append events to `<runtimeDir>/metrics/events-<date>.ndjson` when `metrics.enabled`, and the per-machine `agentctl metrics serve` (`internal/metricsserve`, started by session start and the hook janitor) tails them and reads window logs for usage, with a `project` label on every series. Dispatch completion is hook-driven instead: the hook that sets `Done=true` (Stop hook, `signal done`) stamps `CompleteFiredAt` and spawns a detached `agentctl dispatch-complete <window>` (PR lookup, label swap, open PR, `dispatch_complete` hooks)
5. The state writers (hooks, `signal`, `set-active-window`) rename tmux windows via `internal/winname` inside their windowstate transaction (● working, ⏸ blocked, ! needs attention, ✓ done-unseen, bare name idle; precedence ⏸ > ● > ! > ✓ > ○). A window in a mode that never gets `Done` (bare, discuss, review, custom, improve, no mode) gets the same ✓ at a turn end from the separate `TurnDone` flag (set by the Stop hook, also on an autonomous window's blocked-stop retry, cleared on the next prompt; while a child window is working or blocked it is held as `turn_done_held` and set by `winname.ReleaseTurnDone` when the last busy child goes idle or away); it is display-only and never sets `Done`, so sweep, completion and done counts are unchanged. `!` is windowstate `attention` (`{reason, detail, at}`, display-only like `TurnDone`, not gated by `Seen`): set at a turn end by `hook-check-done` (`turnEndAttention`, `internal/hooks/attention.go`) for `message` (a BLOCKED/NEEDS-BRENDAN verdict recorded by `hooks.recordVerdict` on the reviewer's orchestrator as `pending_verdict`, kept until a human prompt or a later MERGE for that PR), `question` (non-autonomous windows only; `attention.Question`, a pure heuristic over the final assistant text, from the Stop payload or the transcript's last assistant entry) or `errors` (`windowstate.AttentionToolFailures` = 3 consecutive PostToolUseFailures, or a StopFailure); cleared when the window goes working (`winname.Apply`), on UserPromptSubmit and on `/clear`. A new attention sends an `attention` desktop notification (gated by `alert_config.blocked`, skipped while a client views the window). `TurnDone`, `attention`, `pending_verdict` and `turn_count` survive session restore (`restore.json`); restore used to drop them, which left every restored window at ○. `Seen` is a persisted windowstate field. The monitor writes `state.json` (optional token enrichment and restore fallback only); the chrome bar pane (when `chrome_bar` is on) watches `.agentctl/windows/` and `active-window` via fsnotify, rebuilds through `fleet.BuildAgents`, and re-renders only when a rendered field changed

### Dispatch & Worktrees

`agentctl dispatch --issue N` fetches a GitHub issue, creates an isolated git worktree, and launches an agent on it. This is the primary way tickets get assigned to worker agents.

**Worktree layout:**
- Created at `.worktrees/agent-<name>-issue-<N>/` (gitignored)
- Branch: `agent/<agent-name>/issue-<N>`
- Falls back to shared repo dir if worktree creation fails
- Opt out with `--no-worktree`

**Dispatch flow** (in `dispatchIssue()`, `internal/cmd/dispatch.go`):
1. Fetch issue via `gh issue view`
2. Infer agent from issue labels (or use `--agent` flag, default: `go-engineer`)
3. Resolve working directory (from agent config or `--dir`)
4. Create worktree + branch
5. Build prompt with issue body, worktree path, and autonomous execution instructions
6. Launch agent in tmux window via `tmux.LaunchAgent()`

**Worktree package** (`internal/worktree/`): `Create`, `Remove`, `List`, and `Prune` (`git worktree prune`, which cannot delete live work). `agentctl cleanup` and the SessionEnd hook both call `Prune` and treat failure as non-fatal; see "Worktree reclaim on SessionEnd" above.

**Permission mode:** worker dispatches (`--issue`, `--prompt`, `--prompt-key`, `--review-pr`) launch claude with `--permission-mode auto` by default; interactive modes get no flag. Override per agent with `permission_mode` (see [docs/configuration.md](docs/configuration.md#per-agent-settings)).

**Orchestrator agents** (frontmatter `role: orchestrator`, inherited through `extends`): `dispatch.applyAgentRole` upgrades the preamble to the orchestrator one and drops finishing steps and the "do not merge to main" line. A human-initiated ad-hoc launch (the phone's new-session button, or `dispatch --prompt` from a shell with no tracked Claude session) becomes `ModeBare` with the prompt as the first user message (still interactive, no `execInstructions`, but with the worker permission mode: override, agent `permission_mode`, then `auto`); unattended launches (cron, an ad-hoc dispatch from another agent session) and `--issue` keep their mode and autonomy. Workers are unchanged.

**PR review:** `dispatch --review-pr N [--agent code-reviewer] [--author @N] [--prompt ...]` runs `ModeReviewPR` (`internal/cmd/dispatch_review.go`, `internal/dispatch/review.go`): autonomous, worker role, no finishing steps, worktree `agent/<agent>/review-pr-<N>-<id>` cut from the default branch (the reviewer checks out the PR head detached). `dispatch.FetchPR` refuses closed/merged PRs. The author is the live window whose windowstate `branch` equals the PR head branch, across all sessions (`fleet.Load`); when it is on the same account, the prompt names it by `@N.%P` and `mailbox.EnqueueIn` queues an `agentctl notice:` in the author session's mailbox introducing the reviewer. The deliverable is a `REVIEW PR #N — VERDICT: ...` message to the orchestrator. The reviewer gets its own preamble (`reviewerPreamble`: no git conventions or commit-oriented Wait bullets, a `ToolSearch` hint for the deferred `SendMessage`) and orchestrator section, and the PR block carries a diffstat, the CI state at launch (`statusCheckRollup`, same `gh pr view` call) and at most 15 changed files. Context entries: a `ticket-<N>-spec` is injected only on `--issue N` (or when listed in `context_keys`), other agent-scoped entries as before, each cut at 8KB. `reconcile --housekeeping` prunes `<runtimeDir>/launch/` prompt and script files older than 7 days. Config `pr_review` (`always` default, `optional`, `off`; project may override, `Config.EffectivePRReview`) only changes the preamble text built at launch (`dispatch.Request.prReview`, `preambleForHarnessFor`/`preambleWithOrchestratorFor`): `optional` lets the orchestrator skip the review for small PRs, `off` tells it not to dispatch reviewers and drops the "a reviewer may message you" lines from workers. `dispatch --review-pr` and the `dispatch_approval` review exemption are unaffected.

**Cleanup:** `agentctl cleanup` (`internal/cleanup`) classifies every worktree under `.worktrees/` and reclaims the safe ones (see `Classify`'s doc comment). Unknown directories under `.worktrees/` are reported as `skip` and never deleted.

**Sweep:** `agentctl sweep` is the window-centric counterpart, scoped to the *current* tmux session only (session from `$TMUX_PANE`, or `--session` outside tmux). It closes finished windows (including ones with no worktree), reuses `cleanup.Classify` for windows that own one, and lists the rest with the action each needs. Classification is the pure `cleanup.ClassifyWindow`; self, `shell`, `improve~*`, untracked windows, and bare windows (unless `--include-bare`) are never closed. `--include-bare` closes a bare (interactive) window that is idle at a turn end: effective state idle, no pending mail, `turn_count` > 0 (bare windows never get `Done`), no live child windows in any state (`reconcile.IsChild`: `spawned_by` + `spawned_by_session`, any session; closing it would cascade-kill them); it then goes through the same worktree/branch/open-PR checks. The hub keeps bare windows out; serve takes optional `include_bare` on both sweep routes and the phone's sweep sheet has a "Full sweep" toggle (default on). `--dry-run` plans only. The hub (`w`/header `sweep` button) and serve (`POST /v1/sweep/preview`, `POST /v1/sweep`) run it per project as a subprocess through `internal/sweeprun` (`sweeprun.Func` seams `fleetSweep` and `Options.Sweep`, stubbed in tests), never `cmd.RunSweep` in process, which sets the global `tmux.SessionName`.

**`--prompt-key <key>`:** `agentctl dispatch --prompt-key <key> --agent <name>` reads the ad-hoc prompt from the context store instead of `--prompt`. The approval popup sees the raw, unexpanded command, so `--prompt "$(cat spec.md)"` would show a reviewer nothing useful; a context key can be resolved and shown. It is mutually exclusive with `--prompt` and `--issue`. Run `agentctl context set <key> ...` in a **separate Bash call before** the dispatch, not chained with `&&`: the PreToolUse gate runs before any part of the command executes. As a fallback the gate reads a literal `context set <key> <value>` earlier in the same command line (single-quoted, or double-quoted without `$`/backticks); if the prompt still cannot be resolved, the dispatch is denied rather than shown with a placeholder.

### Querying agent status (`agentctl status`)

`agentctl status` is the scriptable counterpart to `agentctl hub` (same `internal/fleet` aggregation). Use it instead of hand-joining `tmux list-windows` with `jq` over windowstate files. Subcommands: `status [<window>]` (table or detail; `--json`, `--session`, `--state`, `--blocked`, `--verify`; `--closed [--since 7d]` lists recently closed windows from `internal/closedlog` instead, plain text), `status peek <window>`, and `status whoami`.

Rows come from `tmux list-windows` plus windowstate (`fleet.LoadAgents`), so `status` works with the monitor off. Two behaviors are deliberate:

- **`PARENT` is blank for bare windows.** Only dispatched windows record a dispatcher; bare windows would otherwise report whichever window was created last (`fleet.Meta.Parent()` returns `""` rather than a plausible wrong answer).
- **`--verify` trusts the pane over the record** via `fleet.ClassifyPane`. `⏸` is not a blocked signal (it is in every pane's footer); classification matches dialog text.

## Adding a transition handler

There is no plugin registry and no handler is registered today. Set `transitionHandlerFn` in `monitor.go` (called by `fireHandlers` from `detectAndFireTransitions()`, under `safeHandle`); it receives the `state.Transition` and the agent's `config.AgentConfig`. The Gone path has the matching optional `reconcile.Deps.Handle`.

## Adding a new subcommand

Add a field to the `CLI` struct in `cli.go` with a `Run()` method (use the `hidden:""` tag for internal-only commands). If it needs a tmux menu, follow the `display-menu`/`display-popup` patterns in `internal/tmux`. If it needs a TUI popup, add a Bubble Tea model in `internal/tui/`.

### Session identity

The window's `SessionID` (written by `hook-session-start`, including after `/clear`) is authoritative for log linking. When set, `linkLogs` links the recorded `LogPath` or derives the log from the session ID (`linkBySessionID`, which calls `sessions.FindLogBySessionIDIn`), and never scans `~/.claude/projects/` for the newest log. Only windows with no SessionID fall back to a scan, confined to the window's own project directory. The statusline drops snapshot data whose log does not match the payload's `session_id`.

Names are not identity. Bare launches name the session `<agent>-<project>-<N>` (`dispatch.SessionNameFor`, N = instance number, known before the window exists), because Claude Code silently renames duplicate `-n` names. The statusline write-back records the `--name`/`/rename` value from `session_name` (ignored when no `-n` was passed, since it is then an AI title; old value kept in `requested_session_name`, `session_name_verified` set); unique launch names, not the write-back, are what prevent dedupe. Restore keeps recorded names but regenerates legacy or duplicate ones (`dispatch.RestoreSessionName`). The only stable keys are the window ID and pane ID (`main_pane`); the tmux session prefix in a ListAgents location (`session:@N.%P`) changes when the hub links windows. The worker preamble therefore names its orchestrator by `@N.%P` and shows the name only when verified. Parent/child linkage uses `spawned_by` plus `spawned_by_session`, never a name.
